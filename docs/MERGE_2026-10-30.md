# Merge log — 2026-10-30

`bugfix` into `main`. Merge commit `639d43d`, six branch commits on top of
`401412f`.

---

## 1. Why this was not a fast-forward

When the branch was first inspected, `main` was at `401412f` and `origin/bugfix`
was 6 ahead, 0 behind — a clean fast-forward. Between that check and the merge,
`main` gained one commit:

```
d5efedd  docs: rewrite README from the current sources
```

So the real shape at merge time was 6 ahead, 1 behind, merge base `401412f`.
A fast-forward was no longer possible, and `git merge` was the only correct
operation.

The lesson: `--ff-only` eligibility is a property of the moment, not of the
branch. Re-check `git rev-list --left-right --count main...branch` immediately
before merging, never from an earlier reading.

## 2. The README conflict was the whole merge

Nineteen files merged cleanly. `README.md` conflicted because both sides had
rewritten it, and they described different code:

| Claim in main's README (`d5efedd`) | Reality after the branch |
|---|---|
| `__dgTelemetry.getStats()` from the page console | The page-world bridge was deliberately removed |
| Offscreen closes 5 minutes after idle | Still a `setTimeout`, still non-durable |
| `models/onnx/` and `models/tokenizer*` are legacy artifacts | Deleted by the branch |
| Title: "HiAnime Live Japanese Subtitles" | Branch is brand-neutral |
| Overlay re-injected after tab reload | Needs host access to the new origin |

Taking either side wholesale would have shipped a README that lies about the
code. `d5efedd`'s structure is the better document — short, one page, no drifted
measurement narrative — so the resolution keeps that structure and applies the
branch's corrections on top:

- brand-neutral title
- teardown timer described as a non-durable `setTimeout`, not a guarantee
- telemetry documented as extension-context only, with the reason the bridge is
  absent
- the cross-origin re-injection caveat restored
- `package.ps1` added to the file table
- the `models/onnx` limitation dropped, since those files no longer exist
- a backpressure bullet, because the PCM queue cap is new behaviour

The rule applied: **the README describes the code that is actually shipped, not
the branch it came from.** Documentation conflicts are resolved by reading the
merged source, not by picking a side.

## 4. Harness changes the merge forced

Two assertions in `domtest.js` no longer matched the code, and both were
harness bugs, not regressions.

**State handle moved.** `contentScript.js` used to park its state on
`window.__dgLiveSubtitleState`. It now uses
`Symbol.for("dg-live-subtitle/state")`, because a page element with a matching
`id` makes string-keyed window access truthy in the isolated world and could
disable the overlay for the whole tab. Symbol keys are unreachable from page
markup.

The harness cannot read that symbol off the sandbox object: a symbol-keyed
property assigned inside a vm context does not surface on the host object.
Verified directly — `Object.getOwnPropertySymbols(sandbox)` is empty after the
context assigns one. The lookup has to be evaluated inside the context:

```js
const state = vm.runInContext(
  'globalThis[Symbol.for("dg-live-subtitle/state")]',
  sandbox
);
```

**The page bridge is gone.** One assertion checked that a `__dg_res_stats`
event reached the page on reset. That bridge was removed on purpose, so the
assertion now checks the opposite: `h.dispatched.length === 0`. `grep` confirms
`contentScript.js` contains no `dispatchEvent`, no `CustomEvent`, and no
`__dg_` string.

Neither change touches the repository.

## 6. Open items carried forward

- **Keep-warm is still not durable.** The branch did not switch to
  `chrome.alarms`; it is still a `setTimeout` that dies with the service worker
  after ~30 s idle. Warm restarts work, the 5-minute cleanup usually does not,
  and the 239 MB model can stay resident until the extension reloads. Fixing it
  needs `"alarms"` in the manifest — a permission change, so it is a decision,
  not a patch.
- **The model is now LFS-tracked.** `.gitattributes` arrived with the branch.
  A fresh clone without Git LFS yields a 134-byte pointer and an ONNX parse
  error, so `git lfs install` / `git lfs pull` is mandatory. The README says so.
- **No measured real-session latency.** Everything above is decode-time and
  reconstruction correctness. `AudioLagMs` has never been checked against a live
  capture, and the new backpressure path only triggers when VAD falls behind
  realtime, which has not been reproduced on real hardware.
- **`window.__dgTelemetry` is still a string key.** The file argues at length
  that string-keyed window flags are page-reachable and uses `Symbol.for()` for
  the boot flag and state, then leaves the telemetry handle on a plain string.
  A page element with `id="__dgTelemetry"` would shadow it in the isolated world
  and make the debug handle unavailable. Cosmetic, not a correctness issue, and
  left alone during a merge.
